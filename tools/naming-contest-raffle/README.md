# 네이밍 공모전 참가상 추첨 프로그램

스마트물관리(SWNM) 네이밍 공모전처럼 **1~3등은 심사로 뽑고, 참가상은 추첨**하는 공모에서
**여러 건을 제출해 당첨 확률을 올리는 행위를 무력화**하는 추첨 도구입니다.

- 파이썬 3.9 이상만 있으면 됩니다. **외부 라이브러리 설치가 필요 없습니다.**
- `raffle.py` **파일 하나만 복사**해도 그대로 동작합니다.
- 입력은 엑셀(`.xlsx`) 또는 CSV. 출력은 엑셀에서 바로 열리는 CSV와 보고용 요약본입니다.

---

## 1. 무엇을 어떻게 막는가

| 문제 | 처리 방식 |
| --- | --- |
| 한 사람이 의미 없는 네이밍을 10건씩 제출해 확률을 올림 | **1인 1표.** 응모 '건'이 아니라 '사람' 단위로 추첨 대상 명부를 만든다. 10건을 내도 응모권은 1장. |
| 이메일 별칭으로 다른 사람인 척함 (`hong+1@gmail.com`, `h.o.ng@gmail.com`) | 이메일을 정규화(`+태그` 제거, gmail 점 제거)해 같은 계정으로 합친다. |
| 휴대폰번호 표기를 바꿔 다른 사람인 척함 (`010-1234-5678` / `+82 10 1234 5678`) | 숫자만 남기는 표준형으로 정규화해 합친다. |
| 동명이인이 한 사람으로 묶여 억울하게 탈락 | **이름은 동일인 판별 근거로 쓰지 않는다.** 이메일·휴대폰번호가 일치할 때만 병합하므로, 이름이 같아도 연락처가 다르면 별개 인원. |
| 최우수·우수 수상자가 참가상까지 중복 수상 | 수상자를 **사람 단위로** 제외한다. 그 사람이 낸 다른 제출건도 함께 빠진다(공고의 "최상위 1건만 시상" 조건 구현). |
| 추첨이 조작되지 않았음을 증명해야 함 | 공개 시드 기반 **결정적 추첨** + 명부 지문(SHA-256). 제3자가 `verify`로 같은 결과를 재현할 수 있다. |

### 동일인 판별 규칙 (요약)

> 두 응모 건은 **정규화된 이메일이 같거나, 정규화된 휴대폰번호가 같을 때** 동일인으로 본다.
> 연결은 전이된다(A—B가 같은 폰, B—C가 같은 메일이면 A·B·C는 한 사람).
> **성명·소속은 병합 근거가 아니다.**

## 2. 준비

### 2-1. 파이썬 설치 확인

```bash
python3 --version    # Windows는 보통  python --version
```

없으면 https://www.python.org/downloads/ 에서 설치합니다(설치 시 *Add Python to PATH* 체크).

### 2-2. 응모 현황 파일 만들기

메일로 받은 응모양식을 엑셀 한 장(첫 시트)에 **1행=열 제목, 2행부터 응모 건**으로 정리합니다.
열 제목은 아래 단어가 들어 있으면 자동으로 인식합니다.

| 항목 | 필수 | 인식되는 열 제목 예 |
| --- | :---: | --- |
| 네이밍(제안명) | ✅ | `네이밍`, `제안명`, `응모작`, `작품명`, `아이디어` |
| 성명 | ✅ | `성명`, `이름`, `응모자` |
| 이메일 | ✅※ | `이메일`, `메일`, `email` |
| 연락처 | ✅※ | `연락처`, `휴대폰`, `전화`, `phone` |
| 소속 | | `소속`, `기관`, `회사`, `학교` |
| 제출일시 | | `제출일시`, `접수일시`, `타임스탬프` |
| 추가 식별정보 | | `생년월일`, `사번`, `학번` |

※ 이메일과 연락처 중 **최소 하나**는 있어야 유효 응모로 인정됩니다(둘 다 없으면 당첨 연락·본인 확인이 불가).
동명이인 구분과 중복 판별 정확도를 위해 **둘 다 받는 것을 권장**합니다.

열 제목이 특이해서 자동 인식이 안 되면 직접 지정하면 됩니다.

```bash
python3 raffle.py inspect -i 응모현황.xlsx --col naming=제출작품 --col phone=연락받을번호
```

빈 서식은 `응모양식_예시.csv`, 채워진 예시는 `sample/응모현황_예시.csv`를 참고하세요.

## 3. 사용법 (3단계)

### 1단계 — 추첨 전 점검

```bash
python3 raffle.py inspect --input 응모현황.xlsx
```

총 응모 건수 대비 **실제 인원**, 다건 제출자, 동명이인 그룹, 무효 응모, 형식이 미흡한 제안을 보여줍니다.
(화면 출력의 개인정보는 마스킹됩니다.)

### 2단계 — 추첨

최우수 1명·우수 2명을 먼저 심사로 확정한 뒤 실행합니다.

```bash
python3 raffle.py draw \
  --input 응모현황.xlsx \
  --winners 10 \
  --reserve 5 \
  --seed "2026-09-15 참가상 추첨 (입회: 홍길동 차장)" \
  --exclude-winner "choi@example.com" \
  --exclude-winner "010-1234-5678" \
  --exclude-winner "정하준" \
  --out 추첨결과
```

| 옵션 | 설명 |
| --- | --- |
| `--winners` | 참가상 인원 (기본 10) |
| `--reserve` | 예비 당첨 인원 (연락 두절·수상 사퇴 대비, 기본 5) |
| `--seed` | **공개 시드.** 추첨 전에 정해 공표하거나 입회자와 함께 기록해 둡니다. 이 값이 결과를 결정합니다. |
| `--exclude-winner` | 최우수·우수 수상자 제외. 이메일·휴대폰번호·성명 중 하나로 지정하며 여러 번 쓸 수 있습니다. 기본 최대 3명(`--max-top-winners`로 변경). |
| `--exclude` | 기타 제외(부적격·본인 사퇴 등). 인원 제한 없음. |
| `--out` | 결과 폴더 (기본 `추첨결과`) |

> 성명으로 제외를 지정했는데 동명이인이 있으면 프로그램이 **중단하고 되묻습니다.** 이때는 이메일이나 휴대폰번호로 다시 지정하세요. 엉뚱한 사람이 조용히 빠지는 일이 없도록 한 장치입니다.

### 3단계 — 검증 (선택)

```bash
python3 raffle.py verify --input 응모현황.xlsx --audit 추첨결과/audit.json
```

같은 명부·같은 시드로 추첨을 다시 계산해 기록과 대조합니다. 감사·이의제기 대응용입니다.
명부가 한 글자라도 바뀌면 지문이 달라져 바로 드러납니다.

## 4. 결과 파일

| 파일 | 내용 | 개인정보 |
| --- | --- | :---: |
| `01_당첨자.csv` | 참가상 당첨자 + 예비 당첨자 (경품 발송·연락용) | 포함 |
| `02_추첨대상_명부.csv` | 추첨에 참여한 전체 인원 1인 1행, 제출건수·비고 포함 | 포함 |
| `03_제외자.csv` | 제외된 사람과 사유 | 포함 |
| `04_무효응모.csv` | 필수항목 누락 등으로 제외된 응모 건 | 포함 |
| `05_확인필요_제안.csv` | 자동 실격시키지 않고 담당자 확인이 필요한 제안 | 포함 |
| `audit.json` | 재현 검증용 기록 (시드·명부 지문·해시값) | **미포함** |
| `report.md` | 보고용 요약 (집계표·당첨자 마스킹 명단·공정성 조치) | 마스킹 |

> CSV는 UTF-8(BOM)로 저장되어 한글 윈도우 엑셀에서 바로 열어도 깨지지 않습니다.
> 당첨자 명단에는 개인정보가 들어 있으므로 공유 폴더 업로드 전 접근권한을 확인하세요.

## 5. 추첨 방식 (검증 가능한 이유)

각 응모자에게 다음 값을 계산해 **오름차순으로 정렬한 뒤 위에서부터 당첨** 처리합니다.

```
추첨해시 = HMAC-SHA256(key = 공개 시드, msg = 응모자 식별키)
응모자 식별키 = 그 사람의 모든 정규화 이메일·휴대폰번호를 정렬해 결합한 문자열
```

- **결정적**: 같은 명부 + 같은 시드 → 항상 같은 결과. 담당자가 마음에 드는 결과가 나올 때까지 돌릴 수 없도록, 시드는 추첨 **전에** 공표하는 것을 권장합니다(예: 추첨일 오전 공지, 입회자 지정 문구, 특정 회차 로또 번호 등).
- **순서 무관**: 명부의 정렬 순서나 엑셀 행 순서를 바꿔도 결과가 같습니다.
- **균등**: 해시 출력은 균등분포이므로 각자의 당첨 확률은 `당첨인원 ÷ 추첨대상 인원`으로 동일합니다(단위 테스트에서 2,000회 반복으로 검증).
- **사후 변조 방지**: `audit.json`의 명부 지문(SHA-256)으로 추첨 후 명부를 고쳤는지 확인할 수 있습니다.

## 6. 운영상 유의사항

- **무의미한 네이밍은 자동 실격시키지 않습니다.** `05_확인필요_제안.csv`에 표시만 하고 판단은 담당자에게 맡깁니다.
  공고문에 없던 실격 기준을 사후에 적용하면 이의제기 소지가 있고, 1인 1표만으로도 다량 제출의 이득은 이미 사라지기 때문입니다.
  명백한 장난성 응모를 제외하려면 `--exclude` 로 사유를 남기며 제외하세요(`03_제외자.csv`에 기록됩니다).
- **공고에 없던 기준을 새로 만들지 마세요.** 이 프로그램이 하는 일은 "1인 1표"와 "최상위 1건만 시상"이라는, 공모 취지상 당연한 원칙을 기계적으로 적용하는 것입니다.
- **개인정보**: 응모자에게 받은 정보는 시상·본인확인 목적에만 쓰고, 수집·이용 동의서를 받아 두세요. `audit.json`과 `report.md`는 개인정보가 없거나 마스킹되어 있어 대외 공개·보고용으로 쓸 수 있습니다.

### 응모양식에 넣으면 좋은 항목

동명이인·중복 판별 정확도를 높이려면 다음을 권장합니다.

1. **휴대폰번호와 이메일을 모두 필수**로 (하나만 받으면 다른 하나로 갈아타 중복 응모가 가능)
2. **소속** (동명이인 육안 확인용)
3. **생년월일**(선택) — 성명+연락처만으로 구분이 애매할 때 담당자 확인용
4. **1인 1건 제출 원칙 및 최상위 1건만 시상** 문구 명시
5. 개인정보 수집·이용 동의 체크
